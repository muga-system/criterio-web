# Módulo 01 · Observar antes de construir

Estado: contrato pedagógico v0 para revisión.

Este documento describe el primer módulo como unidad de aprendizaje. No crea todavía una ruta
Astro, contenido publicado, persistencia ni una isla React.

## Identidad

- **Identificador:** `orientacion-web-01`
- **Título:** Observar antes de construir
- **Área:** Orientación web
- **Prerrequisitos:** ninguno
- **Capacidad central:** convertir una necesidad web poco definida en una decisión explícita y
  verificable.

## Propósito

Antes de aprender una tecnología concreta, el estudiante necesita poder mirar un problema sin saltar
directamente al código. Este módulo introduce una forma simple de separar el pedido, la evidencia,
la decisión y la comprobación.

La intención no es enseñar gestión de proyectos ni producir documentación burocrática. La intención
es construir el hábito de preguntar qué se intenta resolver, qué se puede observar y cómo se sabrá
si la solución funciona.

## Resultado de aprendizaje

Al terminar el módulo, el estudiante debería poder:

- distinguir una petición, un síntoma y un problema;
- identificar información observable y restricciones relevantes;
- formular un criterio de decisión en lenguaje claro;
- elegir una solución inicial explicando su consecuencia principal;
- proponer una verificación concreta antes de considerar terminado el trabajo.

## Secuencia de lecciones

### 01 · Del pedido al problema

**Idea central:** una frase inicial no siempre describe el problema real.

El estudiante compara una petición vaga con el contexto que falta y aprende a formular una pregunta
de trabajo más precisa.

**Práctica propuesta:** transformar tres pedidos breves en una ficha con pedido, síntoma, problema
posible y pregunta pendiente.

### 02 · Evidencia y criterio

**Idea central:** una decisión técnica debe apoyarse en hechos observables y no solo en preferencias.

El estudiante separa observaciones, supuestos y criterios. También identifica qué información aún
no alcanza para decidir.

**Práctica propuesta:** revisar una pantalla o un flujo sencillo y registrar evidencia, restricción
y criterio de aceptación.

### 03 · Decisión y verificación

**Idea central:** una solución es más confiable cuando anticipa cómo será comprobada.

El estudiante redacta una decisión acotada, reconoce su principal trade-off y propone una prueba o
revisión que pueda confirmar el resultado.

**Práctica propuesta:** elegir entre dos soluciones para un problema pequeño y justificar la opción
con un criterio y una verificación.

## Práctica integradora de cierre

Se presenta una necesidad pequeña de Criterio Web sin solución predeterminada. El estudiante debe
entregar una ficha breve con:

1. problema que se intenta resolver;
2. evidencia disponible;
3. restricciones conocidas;
4. criterio de decisión;
5. solución elegida y consecuencia principal;
6. verificación que permitiría cerrar el trabajo.

La práctica no evalúa redacción formal. Evalúa si las partes están relacionadas y si la verificación
responde realmente al criterio declarado.

## Criterio de finalización

El módulo se considera completo cuando:

- las tres lecciones obligatorias fueron recorridas;
- la práctica integradora tiene las seis partes;
- la verificación propuesta es observable y está relacionada con el criterio;
- el estudiante puede explicar por qué eligió esa solución y qué podría hacerla fallar.

No se asignan puntos ni una calificación numérica en esta versión.

## Forma de contenido

Este módulo puede comenzar completamente como contenido estático de Astro:

- explicaciones breves;
- ejemplos escritos;
- fichas de análisis;
- listas de verificación.

No necesita una isla React hasta que una práctica demuestre que la interacción aporta una mejora
real. Si una futura versión permite completar la ficha dentro de la aplicación, esa interfaz será
una candidata para React.

## Decisiones todavía abiertas

- texto definitivo de las situaciones y ejemplos;
- cantidad de ejercicios por lección;
- si la ficha se completa dentro de la interfaz o se responde como revisión guiada;
- evidencia exacta que guardará el progreso;
- relación entre este módulo y el comienzo de HTML semántico.

Estas decisiones deben resolverse al escribir la primera versión de contenido, antes de crear la
ruta individual del módulo.
